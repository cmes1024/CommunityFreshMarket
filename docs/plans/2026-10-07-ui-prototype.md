## 1. 设计目标

- 社区生鲜**预约履约**，非支付电商、非大促风
- 顾客：逛 → 加购 → 配送/自提 → 看单
- 商家：马上处理订单 → 商品/分类 → 时段设置
- 微信小程序习惯：自定义顶栏、Tab、≥44px 触控

第一波界面不做：支付、积分、图像选品、收银、近场会员。

## 3. 页面清单（与产品一一对应）

### 3.1 顾客端 Tab：首页 · 分类 · 商品篮 · 我的

| 页面 | 产品能力 | 原型交互要点 |
|------|----------|----------------|
| 首页 | 店名、履约摘要、进分类 | 配送/自提状态条；类目 chip；商品区按店配置 1/2/3 列加购；英雄区文案可读店配置 |
| 分类 | 本店类目 + 商品列表 | 左类目切换；行内 +/-；底栏去结算 |
| 商品详情 | 有货加购 / 售罄提醒 | 默认半屏抽屉（店可改整页）；完整页保留 |
| 商品篮 | 改数量、结算 | 空态；角标；移除；底栏去结算与分类页同款 |
| 结算 | 配送/自提、地址/时段、备注短语 | 三步指示；提交 loading→成功层 |
| 地址簿/编辑 | 手机小区楼栋室号 | 选择后返回结算 |
| 我的订单 | 列表筛选（可选 UX） | 进详情 |
| 订单详情 | 状态机、取消、客服、再来一单、我到店了 | **横向状态步**；行动区主次分明 |
| 我的 | 地址/订单/联系门店/商家入口 | 联系门店半屏：电话拨打 + 在线客服；成员才显示工作台 |

### 3.2 商家端 Tab：订单 · 商品 · 设置 · 我的

| 页面 | 产品能力 | 原型交互要点 |
|------|----------|----------------|
| 订单台 | 待处理优先、到店标记 | **马上处理**分区；到店脉冲 |
| 订单详情 | 推进/取消 | 横向状态 + 推进按钮 |
| 商品列表 | 上架/有货开关 | 双开关文案正向；链到分类管理 |
| **分类管理** | 本店分类 CRUD | 列表增删启用（单位不管这里） |
| 编辑商品 | 名/价/图/单位枚举/分类下拉 | 单位写死枚举；分类动态 |
| 履约设置 | 时段、联系方式、首页展示 | 头图；文案；列数 1/2/3；点商品半屏/整页；保存反馈 |
| 商家我的 | 回顾客端、邀人 | — |

## 4. 数据绑定约定（防开发写死）

| UI 控件 | 数据来源 |
|---------|----------|
| 顾客左侧类目 / 首页 chip | `GET` 本店启用中的 `category` |
| 编辑商品 · 分类下拉 | 同上 |
| 编辑商品 · 单位下拉 | 客户端/服务端常量：`件` `份` `斤` |
| 自提时段 | 商家履约设置 |
| 首页履约摘要 | 店铺联系/时段配置的只读展示 |
| 点商品半屏或整页 | `store.product_detail_mode`（SHEET 默认 / PAGE） |
| 订单状态文案 | 统一映射表（见产品 §2.4 / 下表） |

## 5. 状态文案

| 状态码 | 配送 | 自提 |
|--------|------|------|
| PENDING_CONFIRM | 待确认 | 待确认 |
| PREPARING | 备货中 | 备货中 |
| DELIVERING | 配送中 | — |
| READY_PICKUP | — | 待自提 |
| COMPLETED | 已完成 | 已完成 |
| CANCELLED | 已取消 | 已取消 |

主按钮：**提交预约** / **加入商品篮** / **到货提醒我**。禁止「去支付」。

### 上架 / 有货

| 开关 | 开 | 关 |
|------|----|----|
| 上架 | 顾客可见 | 不可见 |
| 有货 | 可加购 | 售罄（可见不可买） |

售罄补货 = 打开「有货」（无库存数）。

---

## 6. 关键用户流

1. 预约配送：首页/分类加购 → 篮 → 结算配送+地址 → 提交成功 → 订单  
2. 预约自提：结算切自提 → 选时段 → 提交  
3. 售罄提醒：详情订阅 → 商家改有货 → 通知  
4. 再来一单 / 我到店了：见订单详情  
5. 商家：马上处理 → 推进；商品 → 分类管理 → 编辑商品  
6. 切端：我的 ↔ 商家工作台
