# 社区生鲜私域工具 — UI 原型说明（第一波）

日期：2026-10-07  
状态：可点击 HTML 原型已产出  
可点击原型：[`docs/prototypes/index.html`](../prototypes/index.html)  
依据：产品设计、技术方案

---

## 1. 设计目标

- 服务**社区生鲜预约**，不是综合电商大促风
- 顾客路径短：逛 → 加购 → 配送/自提 → 看单
- 商家路径清：待处理订单优先，商品与时段设置次之
- 贴合微信小程序习惯：自定义顶栏、底部 Tab、大触控区

第一波不做：支付、积分、图像选品、收银、近场会员相关界面。

---

## 2. 视觉方向：「晨市绿摊」

清晨菜场摊位感——干净、好辨认价格与有货状态，偏工具轻品牌。

| Token | 值 | 用途 |
|-------|-----|------|
| `--green-ink` | `#16382A` | 主文案 |
| `--green-deep` | `#1F6B4A` | 主色 / Tab 选中 / 主按钮 |
| `--green-mist` | `#E7F0EB` | 浅底、选中块 |
| `--leaf` | `#3D9B6E` | 辅助强调 |
| `--citrus` | `#E8911C` | 价格、待处理角标（避免紫系） |
| `--fog` | `#F3F6F4` | 页面底 |
| `--line` | `#D5E0D9` | 分割线 |
| `--danger` | `#C23B2A` | 售罄、取消 |
| `--ok` | `#2A7A4F` | 成功/有货 |

字体（原型）：标题用 **ZCOOL QingKe HuangYou**（展店名），正文 **Noto Sans SC**。小程序落地时可改为系统字体 + 店名字重区分。

氛围：雾绿底 + 极淡斜向纹理；列表行作交互容器，避免堆叠卡片与紫色渐变。

## 3. 信息架构（第一波页面）

### 3.1 顾客端

| 页面 | 作用 |
|------|------|
| 首页 | 店名英雄级露出、进分类、推荐位可空 |
| 分类 | 左类目 + 右商品列表 |
| 商品详情 | 图、价、单位、有货、加购 |
| 商品篮 | 改数量、去结算 |
| 结算 | 配送/自提切换；地址或时段；备注；提交预约 |
| 地址列表 / 编辑 | 手机、小区、楼栋、室号 |
| 我的订单 / 详情 | 状态、取消、微信客服；再来一单；待自提「我到店了」 |
| 商品详情（售罄） | 「到货提醒我」 |
| 结算 | 配送/自提 + **备注快捷短语** |
| 我的 | 地址、订单、客服；成员可见「商家工作台」 |

Tab：首页 · 分类 · 商品篮 · 我的

### 3.2 商家端

| 页面 | 作用 |
|------|------|
| 订单台 | 待处理优先 + 红点；推进 / 取消 |
| 订单详情 | 履约信息、状态操作 |
| 商品管理 | 列表、有货/售罄、上下架入口 |
| 编辑商品 | 名、价、单位、图、分类 |
| 履约设置 | 自提时段、店铺联系方式 |
| 商家我的 | 回顾客端 |

Tab：订单 · 商品 · 设置 · 我的

---

## 4. 关键用户流（原型可点通）

1. **顾客预约配送**：首页 → 分类 → 详情加购 → 篮 → 结算选配送+地址 → 提交 → 订单详情  
2. **顾客预约自提**：结算切自提 → 选时段 → 提交  
3. **商家接单**：订单台（红点）→ 详情 → 待确认→备货→配送中/待自提→完成  
4. **取消**：订单详情「取消订单」（未完成）  
5. **切端**：顾客「我的」→ 商家工作台；商家「我的」→ 回顾客端  

---

## 5. 文案与状态映射

| 状态码 | 配送文案 | 自提文案 |
|--------|----------|----------|
| PENDING_CONFIRM | 待确认 | 待确认 |
| PREPARING | 备货中 | 备货中 |
| DELIVERING | 配送中 | — |
| READY_PICKUP | — | 待自提 |
| COMPLETED | 已完成 | 已完成 |
| CANCELLED | 已取消 | 已取消 |

售罄商品：列表打「售罄」、详情主按钮禁用。  
结算主按钮文案：**提交预约**（非「去支付」）。

### 商家商品两个开关（第一波）

| 开关 | 开 | 关 |
|------|----|----|
| **上架** | 顾客分类/搜索可见 | 顾客端不可见（下架） |
| **有货** | 可加购下单 | **售罄**：仍可看见，不可加购 |

第一波无库存数量；「补货上架」= 保持上架，并把 **有货** 重新打开（不必填库存）。真实扣库存是第二波。
