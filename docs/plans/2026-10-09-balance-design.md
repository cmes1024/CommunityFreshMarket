# 储值余额

日期：2026-10-09  
状态：按此实现

当面收的现金记入顾客余额，预约时抵应付。不走积分，不接微信支付。

---

## 1. 边界

余额模块自己管账户和流水。订单、积分、优惠券只在下面三个时刻打交道：

- 提交预约：优惠券算完后，若顾客选择使用余额，扣 `min(余额, 应付)`。应付 = 商品合计 − 券抵扣。
- 取消未完成单：把该单扣过的余额退回。退一次即可。
- 订单完成：积分仍按优惠后的订单金额入账，不因用了余额而少记。充值本身不加积分。

配送起送仍按商品合计，不看余额。斤的数量就是下单数量，不另做称重改价。

认人复用现成的会员码解析和冒泡名单。充值成功后这次冒泡用掉，避免同一下气泡被记两次。

## 2. 数据

```text
balance_account (user_id, store_id, balance_fen, updated_at)
balance_ledger  (id, store_id, user_id, delta_fen, balance_after_fen,
                 reason TOPUP|SPEND|REFUND, ref_type, ref_id,
                 operator_user_id, remark, created_at)
```

`order.balance_fen` 记下本单实际抵了多少，方便展示和退回。扣款以流水为准，订单字段是快照。

余额按分存，不能为负。并发下用「读到的余额等于更新条件」避免两笔单扣穿；撞上了让顾客重试。

## 3. 接口

- `GET /api/v1/balance/me`：余额和最近流水
- `POST /api/v1/merchant/balance/topups`：`{ code | checkinId, amountFen }`
- 提交预约增加 `useBalance`。未传或 false 不扣。

## 4. 界面

- 顾客「我的」进入余额页，看金额和流水。
- 结算在有余额时默认勾上「使用余额」，可关掉。账单写出抵扣和还需当面付的金额。抵光时写明本单不用再付款。
- 商家「我的」有「储值」，扫会员码或点正在冒泡的人，填现金金额后入账。

## 5. 验收

- 充值增加余额，不增加积分。
- 下单可部分抵扣，剩下的仍当面收；取消后余额回到扣之前。
- 不用余额时，订单和余额都不变。
- 完成订单的积分仍按券后金额，与是否使用余额无关。
