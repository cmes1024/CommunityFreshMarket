日期：2026-10-07  
状态：头脑风暴对齐稿

## 1. 产品定位与分期

### 1.1 定位

面向中小商户（商店、小型超市、个体户）的**私域经营工具**。

- 载体：微信小程序（顾客端 + 商家端）
- 后端：Java 自建服务（避免云函数调用次数限制）
- 不做在线支付；聚焦商品介绍、预约履约与会员经营；当面收款由线下完成

### 1.2 形态策略

- **先单店可用**，数据与权限按「店铺」隔离
- 架构**预留多店平台**（选店 / 切店），第一版不做平台型首页
- 无 PC 端；若日后需要运营后台，另做 Web，与店员小程序分离

### 1.3 分期

| 波次 | 能力 |
|------|------|
| **第一波** | 分类与商品、商品篮、地址簿；预约下单（配送/自提）；商家订单流转；微信客服；有货/售罄；订阅消息 + 待处理红点；**顾客增补四项**（见 §2.7） |
| **第二波** | 会员积分；图像选品；简单库存扣减；（可选）店长时令手写、缺货替代 |
| **第三波** | 优惠券；到店扫码收银；附近会员 / 快速定位 |

## 2. 信息架构与主流程

### 2.1 小程序结构

- **一个 AppID**
- **顾客分包 / 商家分包**，两套首页，按当前模式加载
- 目的：低耦合、控制主包体积

### 2.2 顾客端

主入口：首页 · 分类 · 商品篮 · 我的

- **首页**：本店入口、推荐位（可先空）、快捷进分类
- **分类**：类目 → 列表 → 详情（名称、图、单位、价、有货状态）→ 加购；售罄可「到货提醒我」
- **商品篮**：改数量 → 结算
- **我的订单 / 详情**：状态、取消、客服；已完成可「再来一单」；待自提可「我到店了」
- **我的**：地址簿、我的订单、联系客服；（第二波）积分；若为店铺成员则显示「商家工作台」

### 2.3 下单主路径

选品加购 → 结算选**配送或自提** →

- 配送：选地址簿地址 +「尽快」+ 备注（备注支持快捷短语）
- 自提：选商家配置的可约时段

→ 提交预约 → 订单详情（状态、取消、微信客服）

### 2.4 订单状态（共用一套，文案随履约变）

`待确认` → `备货中` → `配送中` / `待自提` → `已完成`

任意**未完成**单：顾客与商家均可取消；也可经订单页微信客服协商后取消。

### 2.5 商家端

- **订单台**：待处理优先 + 红点；推进状态；可取消；展示顾客「我到店了」标记
- **商品**：分类、上下架、有货/售罄、价与单位（件/斤）；改回「有货」时触发到货提醒推送
- **履约设置**：自提可约时段；店铺联系方式
- **消息**：订阅消息（新单/取消/到货提醒/顾客到店）；日常以打开订单台为准
- **我的**：回顾客端；成员邀请（店主冷启动后）

### 2.6 履约规则（第一波）

| 方式 | 时间 | 地址 |
|------|------|------|
| 自提 | 商家预设时段，用户只能选时段 | 到店 |
| 配送 | 尽快 + 备注 | 地址簿：手机号、小区、楼栋、室号等 |

计价单位第一波：`件/份` + 简单`斤`；更复杂计量后补。

库存第一波：手控「有货 / 售罄」；表结构预留库存字段，第二波再扣减。

客服第一波：微信小程序客服；预留日后自建订单会话。

### 2.7 顾客端增补（第一波，已拍板）

只做紧扣「预约履约 + 复购」、且不碰支付/库存数量的能力：

| 能力 | 规则 |
|------|------|
| **再来一单** | 已完成（或历史）订单详情一键将当时商品加回商品篮；已下架/售罄的行跳过并提示 |
| **售罄 · 到货提醒我** | 售罄详情可订阅；店员将该商品改回「有货」时发订阅消息（失败不阻断改状态）；同一用户同一商品未提醒前不重复堆积 |
| **自提 · 我到店了** | 订单为「待自提」时顾客可点一次；订单打标 + 商家订单台红点/订阅；不可重复点 |
| **备注快捷短语** | 结算页预设若干短语（如放门口、少葱、称重点、不要电话），可多选拼进备注，仍可手改 |

**第一波明确不做的顾客创意**（避免分心）：家庭口味档案、邻居同款、缺货智能替代、内容社区/拼单、游戏化。  
**第二波及以后可再评估**：店长时令手写、缺货替代、斤两说明字段加强等。

## 3. 账号、角色与商店维度

### 3.1 原则

- 所有人默认都是**顾客**（微信登录即可）
- **不要**启动时的全局角色选择页
- 商家能力 = 额外权限，不是互斥身份

### 3.2 角色

| 角色 | 含义 | 「商家工作台」入口 |
|------|------|-------------------|
| 顾客 | 所有登录用户 | 无（除非同时是成员） |
| 店主 | 原「超级管理员」；管本店、邀店员 | 有 |
| 店员 | 协助经营 | 有 |

第一版：**店主与店员能力相同**；成员表保留角色字段，以后再收紧权限。

### 3.3 登录与冷启动

- 小程序内**不做账密**；始终微信登录（openid → 用户）
- 权限只看 `店铺成员`（userId + storeId + 角色）
- 冷启动：开发版先登录，将某用户写入某店**店主**；其后店主邀请绑定店员（支持多 openid）
- 平台运维若需建店/绑店主，可用后台或刷库，**不作为小程序内产品角色**

### 3.4 商店维度（多店扩展槽）

从第一天起，商品、订单、时段、成员等均带 `storeId`。

- 顾客侧：`browseStoreId`（单店=唯一店；多店=选店）
- 商家侧：`manageStoreId`（单店直接进；多店可切换对应店工作台）
- 同一人可在 A 店为店主、B 店为店员

## 4. 领域对象（产品级）

- **店铺**
- **用户** + **收货地址**
- **店铺成员**
- **分类 / 商品**（单位、价格、有货状态；库存字段预留）
- **自提时段**
- **订单**（履约方式、状态、地址或时段、备注、取消信息）
- 第二波起：积分账户与明细、实景点选会话、优惠券、收银单、附近会员会话等

---

## 5. 第二波轮廓

### 5.1 会员积分

- 订单**已完成**后，按金额 × 店铺积分比例入账
- 顾客：余额、明细、兑换（兑换物商家配置；可先「记录 + 线下履约」）
- 商家：配置比例；调整需留痕（细则后补）
- 到店收银（第三波）完成后同样可触发积分

### 5.2 图像选品

挂在商品详情的附加能力（水果/生鲜等）：

1. 可普通加购，或**申请实景选品**
2. 商家上传实景图；有效期 **N 分钟**（店铺可配）
3. 顾客在图上点选打标，作为选品凭证（非视频）
4. **同一实景图同时仅一个选品会话**（锁定），避免抢筐
5. 商家按标记取货 → 确认 → 可更新实景图供下一位
6. 选品结果进入订单明细，再走原有履约

无实景时不影响普通加购。

---

## 6. 第三波轮廓

- **优惠券**：自建，不依赖微信卡券；简单满减/固定面额；领取、抵扣意向、核销记录
- **到店收银**：多商品扫码合计；挂会员（手机号或快速定位）；临时改价/打折，原因可选并落库；支付线下
- **会员快速定位**：约 500 米内会员列表；或顾客主动「快速报到」短时效（如 2 分钟）推送供店员点选；黑名单弱提示；会员等级后置

## 7. 技术骨架

| 层 | 选型 |
|----|------|
| 客户端 | 微信小程序；分包；微信登录；订阅消息；微信客服 |
| 服务端 | Java API |
| 数据 | 关系库；按 `storeId` 隔离 |
| 扩展 | 单店先跑通；多店加选店/切店，不推倒模型 |

第一波成功标准：一家店能上架；顾客能预约配送/自提；店员能在手机上把单推到完成；取消与客服路径通；新单有基本感知；再来一单 / 到货提醒 / 我到店了 / 备注短语可用。

---

## 8. 第一波明确不做

在线支付、真实库存扣减、图像选品、积分/券/收银/快速定位、店员细权限、PC 端、小程序账密登录；邻居同款、拼单社区、游戏化、家庭口味档案。
