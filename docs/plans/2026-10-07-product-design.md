## 1. 产品定位与分期

### 1.1 定位

面向中小商户（商店、小型超市、个体户）的**私域经营工具**。

- 载体：微信小程序（顾客端 + 商家端）
- 后端：Java 自建服务（避免云函数调用次数限制）
- 不做在线支付；聚焦商品介绍、预约履约与会员经营；当面收款由线下完成

### 1.2 形态策略

- **先单店可用**，数据与权限按「店铺」隔离
- 架构**预留多店平台**（选店 / 切店），第一版不做平台型首页
- 无 PC 端；若日后需要运营后台，另做 Web，与店员小程序分离

### 1.3 分期

| 波次 | 能力 |
|------|------|
| **第一波** | 分类与商品、商品篮、地址簿；预约下单（配送/自提）；商家订单流转；微信客服；有货/售罄；订阅消息 + 待处理红点；**顾客增补四项**（见 §2.7） |
| **第二波** | 会员积分；商品实景图；简单库存扣减；商品起购 / 限购；（可选）店长时令手写、缺货替代 |
| **第三波** | 优惠券；预约单积分；到店按金额补记积分（会员码 / 冒个泡） |

## 2. 信息架构与主流程

### 2.1 小程序结构

- **一个 AppID**
- **顾客分包 / 商家分包**，两套首页，按当前模式加载
- 目的：低耦合、控制主包体积

### 2.2 顾客端

主入口：首页 · 分类 · 商品篮 · 我的。门店可将会员码放到这四个中间（首页 · 分类 · 会员码 · 商品篮 · 我的）。点会员码进入现有会员码页，返回回到刚才的 Tab。默认仍在「我的」。

- **首页**：导航左上角固定店名；头图区可配营业状态 / **主标题** / 副标题（主标题留空则不展示，避免与导航店名重复；未配头图用品牌色底）；履约摘要（配送已设起送金额时该行显示「满 x 元起送」，否则「尽快出发」）；类目快捷；**推荐位**只展示商家标了「首页推荐」且已上架的商品，列数 **1/2/3** 可配；未配置推荐则空态引导去分类；分类页仍用通栏列表（不看推荐标记）
- **分类**：左类目（来自本店分类）+ 右商品列表；**列表内 +/- 加购**（不必先进详情）；有选购时底栏「去结算」；点商品按店配置开半屏或整页
- **商品详情**：图（最多 3 张，半屏/整页 **轮播**；仅 1 张不显示指示点）、名、单位、可选规格说明、价、有货/售罄；**购买须知**读店铺配置（空则不展示该模块）；副文案见 §2.5；有货：步进器 + 加购；售罄：主按钮改为「到货提醒我」（订阅消息）。首页/分类点商品默认半屏 `page-container`（能力与详情页一致，商家可改整页）；完整详情页保留供外链与「整页」配置。列表/商品篮只用**封面图**（第一张）
- **商品篮**：改数量 / 移除；角标展示件数；空态引导去分类；底栏「去结算」与分类页同款（胶囊合计条）
- **结算**：配送/自提切换；配送选地址簿 +「尽快」+ 备注短语；自提选商家时段；有余额时默认使用，可关掉，账单显示余额抵扣和还需当面付的金额；主按钮 **提交预约**（loading → 成功再进订单）。营业状态为「打烊了」时，按钮正上方显示同宽的大号打烊提示（仍可提交，店员营业后再处理）
- **我的订单 / 详情**：横向状态进度（与 §2.4 状态机一致，文案随履约变）；取消前二次确认；微信客服；已完成「再来一单」；待自提「我到店了」
- **我的**：身份卡保持头像加名字，右侧「编辑」打开半屏再改头像和昵称。地址簿、我的订单、**联系门店**（半屏：门店电话可拨打 + 在线客服）、会员码（出示二维码，旁边可「冒个泡」）；（第二波）积分；店铺成员显示「商家工作台」。会员码改放底栏后，这张卡不显示。成员冷启动已在商家端，此入口给从顾客端返回后再次进入

### 2.3 下单主路径

选品加购 → 结算选**配送或自提** →

- 配送：选地址簿地址 +「尽快」+ 备注（备注支持快捷短语）
- 自提：选商家配置的可约时段

→ 提交预约 → 订单详情（状态、取消、微信客服）

### 2.4 订单状态（共用一套，文案随履约变）

`待确认` → `备货中` → `配送中` / `待自提` → `已完成`

任意**未完成**单：顾客与商家均可取消；也可经订单页微信客服协商后取消。

### 2.5 商家端

- **订单台**：顶栏用状态导航切换列表，避免各状态通铺成长列表。默认 **「马上处理」**（待确认、顾客已到店）+ 红点/强调；其余页签为备货中、配送中、待自提，各签只显示该列表并带数量。顾客已到店的单在「马上处理」和「待自提」都可见。列表内可推进、可取消（取消前二次确认）
- **商品列表**：**两列卡片**。有封面时图铺满整张卡片作背景，名称（最多两行）、价格、规格叠在图上；无图则白底。卡底一行三个状态：**上架/下架、有货/售罄、推荐**，点一下切换。点卡片图文进编辑；入口进 **分类管理**；支持按名称模糊搜索，并按分类（一行横滑，分类多了左右滑）、首页推荐、上架/下架、售罄筛选。**批量**：进入多选后可先筛选再全选当前列表，统一上架、下架、有货、售罄、推荐、取消推荐或删除。编辑页可删除单个商品。删除后顾客端与商品篮不再出现；历史订单保留当时的名称和价格，未完成单仍按原明细履约
- **分类管理**：本店分类 CRUD（名称、排序、启用）；顾客端左侧类目与加购下拉均读此数据
- **编辑/新增商品**：名称、**图片最多 3 张**（可增删；顺序=轮播顺序，第一张=封面）、价格、**单位（系统枚举）**、可选**规格说明**、**分类（本店分类下拉）**、**首页推荐**（默认关）；上架/有货/首页推荐均可在列表快捷切换；改回「有货」时触发到货提醒。已有商品可在本页删除（二次确认）
- **门店设置**（顶栏导航切换「门店、首页、积分、实景、自提」，一次只显示一组；分组为门店信息、首页配置、积分、商品实景、自提）：自提可约时段（添加或删除后立即生效）；店铺联系方式；**购买须知**（原「履约说明」，可空；有内容才在商详/半屏展示）；**备注快捷短语**分配送、自提两套，门店设置里收在同一块，用导航切换（各最多 8 句，每句最多 8 个字；某一套留空则该履约方式不显示短语，只留手写；已有店铺两套都先带上「放门口、少葱、称重点、不要电话」）；**配送起送金额**（元，不填或 0 为不限制，随「保存设置」提交）；**首页展示**：头图、营业状态（可点「营业中」或「打烊了」填入，文本仍可手改）、主标题（头图大字，留空不显示）、副标题、商品列数（1/2/3）、点商品打开方式（半屏默认 / 整页）；导航店名=店名。积分比例、会员码入口（我的 / 底栏，默认我的）、实景有效时间与备注短语随「保存设置」提交
- **消息**：订阅消息（新单/取消/到货提醒/顾客到店）；日常以打开订单台为准
- **我的**：回顾客端；**邀请店员**（弹普通链接二维码 → 扫码进无入口的「加入门店」页并预填 `code`；可更换码；页不可分享；冷启动 `BOOTSTRAP_OWNER_OPENID` 仍可用）

#### 单位与分类如何管理

| 项 | 管理方式 | 添商品时 |
|----|----------|----------|
| **图片** | 最多 3 张；第一张为封面（列表/篮）；详情半屏与整页轮播全量 | 可空；可增删排序 |
| **单位** | 系统枚举，第一波固定：`件` / `份` / `斤` | 下拉只读枚举，店员不可自定义 |
| **规格说明** | 可选短文案（如「约 10 枚」「约 500g/份」）；盒/袋等包装写进说明，不扩单位枚举 | 可空；件/份建议填清顾客看不清的含量 |
| **分类** | 商家「分类管理」维护，表 `category` + `store_id` | 下拉 = 本店已启用分类 |

#### 单位副文案（顾客端）

有货：先展示规格说明（若有）；单位为「斤」时固定追加当面称重提示（详情/半屏「当面称重为准」，列表可用短句）；件/份且无规格则只显示单位。售罄：只拼「今日已售完」，不拼规格/称重。

### 2.6 履约规则（第一波）

| 方式 | 时间 | 地址 |
|------|------|------|
| 自提 | 商家预设时段，用户只能选时段 | 到店 |
| 配送 | 尽快 + 备注 | 地址簿：手机号、小区、楼栋、室号等 |

配送起送默认关闭。门店填了金额后，只在提交配送预约时按商品合计（用券前的预估）比较，未满则不能提交；自提不限制。斤为约重，当面称重后的实收仍在线下完成。订单不保存该门槛。

计价单位第一波：`件/份` + 简单`斤`；更复杂计量后补。

库存第一波：手控「有货 / 售罄」；表结构预留库存字段，第二波再扣减。

客服第一波：微信小程序客服；预留日后自建订单会话。

### 2.7 顾客端增补（第一波，已拍板）

只做紧扣「预约履约 + 复购」、且不碰支付/库存数量的能力：

| 能力 | 规则 |
|------|------|
| **再来一单** | 已完成（或历史）订单详情一键将当时商品加回商品篮；已下架/售罄的行跳过并提示 |
| **售罄 · 到货提醒我** | 售罄详情可订阅；店员将该商品改回「有货」时发订阅消息（失败不阻断改状态）；同一用户同一商品未提醒前不重复堆积 |
| **自提 · 我到店了** | 订单为「待自提」时顾客可点一次；订单打标 + 商家订单台红点/订阅；不可重复点 |
| **备注快捷短语** | 配送、自提各一套，门店设置里同一块用导航切换着维护，每套最多 8 句、每句 8 个字。结算只显示当前履约方式的短语，可多选拼进备注，仍可手改。某一套未配置则该方式不显示短语 |

**第一波明确不做的顾客创意**（避免分心）：家庭口味档案、邻居同款、缺货智能替代、内容社区/拼单、游戏化。  
**第二波及以后可再评估**：店长时令手写、缺货替代、结构化含量（枚数/克重）等。

### 2.8 UI / 交互与产品对齐（开发以本节 + UI 原型为准）

下列为原型 v2 已采纳、**属于产品能力而非纯视觉装饰**，实现时不得省略或改成另一套流程：

| 能力 | 产品要求 |
|------|----------|
| 列表加购 | 分类通栏行 / 首页 1·2·3 列商品区均支持行内加购；点商品默认半屏详情（商家可改整页）；与详情加购写入同一商品篮 |
| 篮角标 / 结算底栏 | 有件数时 Tab 角标；分类页与商品篮底栏同款胶囊条展示合计并「去结算」 |
| 提交反馈 | 提交预约须有进行中态与成功确认，再进入订单详情 |
| 订单进度展示 | 详情用进度条/步骤展示 §2.4 状态，禁止另造状态文案 |
| 订单台分区 | 状态导航切换「马上处理 / 备货中 / 配送中 / 待自提」，一次只看一个列表；「顾客已到店」强提示 |
| 分类数据源 | 顾客类目、商家商品分类下拉，一律来自本店分类管理 |
| 单位数据源 | 仅系统枚举；编辑页不得开放自由输入单位；含量用可选规格说明 |
| 单位副文案 | 按 §2.5：斤才固定称重提示；件/份不误显称重句 |
| 商品多图 | 最多 3 张；列表/篮用封面；详情半屏与整页轮播；商家列表紧凑行 + 双开关 |
| 主 CTA 文案 | 「提交预约 / 加入商品篮 / 到货提醒我」，禁止「去支付」 |

视觉令牌与组件细节见 `design-system/communityfreshmarket/MASTER.md` 与 `docs/plans/2026-10-07-ui-prototype.md`。

## 3. 账号、角色与商店维度

### 3.1 原则

- 所有人默认都是**顾客**（微信登录即可）
- **不要**启动时的全局角色选择页
- 商家能力 = 额外权限，不是互斥身份
- 店铺成员（店主、店员）打开小程序直接进入商家订单台；商家「我的」仍可回顾客端

### 3.2 角色

| 角色 | 含义 | 「商家工作台」入口 |
|------|------|-------------------|
| 顾客 | 所有登录用户 | 无（除非同时是成员） |
| 店主 | 原「超级管理员」；管本店、邀店员 | 有 |
| 店员 | 协助经营 | 有 |

第一版：**店主与店员能力相同**；成员表保留角色字段，以后再收紧权限。

### 3.3 登录与冷启动

- 小程序内**不做账密**；始终微信登录（openid → 用户）
- 权限只看 `店铺成员`（userId + storeId + 角色）
- 冷启动：部署配置 `BOOTSTRAP_OWNER_OPENID`（店主微信 openid）；该账号登录后自动成为默认店**店主**（本地与生产同一机制）。其后店主邀请绑定店员（支持多 openid；邀请能力可后补）
- 亦可运维刷库写入 `store_member`；**不在小程序内做开发专用绑店主入口**

### 3.4 商店维度（多店扩展槽）

从第一天起，商品、订单、时段、成员等均带 `storeId`。

- 顾客侧：`browseStoreId`（单店=唯一店；多店=选店）
- 商家侧：`manageStoreId`（单店直接进；多店可切换对应店工作台）
- 同一人可在 A 店为店主、B 店为店员

## 4. 领域对象（产品级）

- **店铺**
- **用户** + **收货地址**
- **店铺成员**
- **分类 / 商品**（单位、价格、有货状态；库存 / 起购 / 限购字段预留第二波）
- **自提时段**
- **订单**（履约方式、状态、地址或时段、备注、取消信息）
- 第二波起：积分账户与明细、商品实景图、起购限购校验、优惠券、到店补记积分、储值余额（与积分分开）

## 5. 第二波轮廓

### 5.1 会员积分

- 订单**已完成**后，按金额 × 店铺积分比例入账
- 顾客：余额、明细、兑换（兑换物商家配置；可先「记录 + 线下履约」）
- 商家：配置比例；调整需留痕（细则后补）
- 已是小程序会员、但这笔走了店里收银机时，店员扫会员码或点「冒个泡」的人，按消费金额补记积分

### 5.2 商品实景图

挂在商品详情和半屏的附加图，用来看新鲜度。普通加购不受影响。细则见 `docs/plans/2026-10-08-live-photo-design.md`。

- 商品编辑页「支持实时图」默认关。关闭时顾客看不到实景图，也不能申请。
- 打开后，有图则详情/半屏第一张是实景图并带拍摄时间；无图则第一张是占位，可「申请更新图片」。
- 超过店铺配置的有效时长后，旧图仍留在第一张，右下角出现「申请更新图片」。
- 申请进商家站内信，同一商品合并为一条并显示人数；点开进入该商品编辑页。商家用相册或相机提交新图后申请消失。
- 不做打标、一图一锁、确认进篮。

### 5.3 商品起购 / 限购

与简单库存扣减同期评估落地（第一波仅有货/售罄，不做数量硬卡）：

- **起购**：单行加购数量下限（如鸡蛋最少 2 份）；未配则仍按单位步进最小值
- **限购**：单行加购数量上限（如特价每人限 1）；未配则不设上限；若与库存并存，取更严者
- **作用面**：分类行内 +/-、详情/半屏步进器、商品篮改数量、再来一单写入篮时跳过或截断超限并提示
- **商家编辑**：商品编辑页可选填；空 = 不限制；文案对顾客可见（价旁或步进器旁短提示）
- **明确不做（本能力内）**：按会员等级差异限购、按自然日 / 活动场次限购、全店统一起购（可后补）

## 6. 第三波轮廓

- **优惠券**：自建，不依赖微信卡券；简单满减/固定面额；领取后挂在预约单上，不在现场收银机那笔记
- **到店补记积分**：不做自建收银。店里已有收银机收款。已在小程序里的会员到店现场购买时，顾客出示会员码，店员扫码后填写收银机上的金额，按店铺积分比例入账。扫不了时，会员码旁边点「冒个泡」，2 分钟内出现在店员「记积分」名单里，显示头像和昵称，入口有红点；点中后填同一笔金额，记完这次冒泡用掉。只在收银机消费、没用过小程序的人，不从这里拉进来。预约单完成仍自动记积分
- **储值余额**：顾客当面把现金给店员，店员扫会员码或点「冒个泡」后按金额充进余额。结算先减优惠券，再用余额抵应付，不够的部分仍当面收。取消未完成单时退回本单扣掉的余额。余额与积分分开记账；充值不加积分，订单完成仍按券后金额入积分。细则见 `docs/plans/2026-10-09-balance-design.md`

## 7. 技术骨架

| 层 | 选型 |
|----|------|
| 客户端 | 微信小程序；分包；微信登录；订阅消息；微信客服 |
| 服务端 | Java API |
| 数据 | 关系库；按 `storeId` 隔离 |
| 扩展 | 单店先跑通；多店加选店/切店，不推倒模型 |

第一波成功标准：一家店能上架；顾客能预约配送/自提；店员能在手机上把单推到完成；取消与客服路径通；新单有基本感知；再来一单 / 到货提醒 / 我到店了 / 备注短语可用。

---

## 8. 第一波明确不做

在线支付、真实库存扣减、图像选品、积分/券/收银/快速定位、店员细权限、PC 端、小程序账密登录；**商品起购 / 限购**（第二波）；邻居同款、拼单社区、游戏化、家庭口味档案。
