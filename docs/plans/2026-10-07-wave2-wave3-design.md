## 0. 本会话默认决策（无需产品再拍板）

| 议题 | 默认 |
|------|------|
| 库存 `stock_qty` | `NULL`=不限数量（仍看 `in_stock`）；有值则硬卡；数量用 `DECIMAL(10,2)` 与篮一致 |
| 扣减时机 | **提交预约单成功时**扣减；**取消**回滚；扣到 0 → 自动 `in_stock=false`；回滚后若库存>0 → 自动 `in_stock=true` |
| 起购/限购 | `min_qty`/`max_qty` 可空；与库存并存取更严；作用于加购/改数量/再来一单 |
| 积分比例 | 店铺 `points_per_yuan DECIMAL(5,2)`（默认 1，最多两位小数，0=关闭）：每满 1 元入账 `floor(floor(应付分/100)*比例)`，积分仍记整数；**订单 COMPLETED 时**入账一次 |
| 积分兑换 | 先「兑换申请 + 线下履约」；商家确认核销；不做线上支付抵扣 |
| 商品实景图 | 见 `2026-10-08-live-photo-design.md`。商品级开关默认关；详情/半屏第一张为实景图；超时可申请更新；站内信合并计数；相册或相机提交后申请消失。有效时长仍用 `pick_image_ttl_minutes`（默认 15 分钟）。不再做打标、一图一锁、确认进篮 |
| 第二波可选 | **不做**店长时令手写、缺货替代 |
| 优惠券 | 自建满减/固定面额；领取后下单可挂「抵扣意向」；核销记流水；不接微信卡券。现场收银机那笔不在这里核销 |
| 到店补记积分 | 不做自建收银。已是会员、但这笔走了店里收银机时：店员扫会员码，或点「冒个泡」名单里的人，填写消费金额，按 `points_per_yuan` 入账。冒泡名单显示头像和昵称，有效 **2 分钟**，记完用掉；「记积分」入口有红点。顾客在「我的」点「编辑」，半屏里选头像、填昵称。只在收银机消费的人不拉进小程序 |
| 配送起送 | `min_delivery_fen` 默认 0（不限制）。只在提交配送时按商品合计（券前预估）比较；自提不看。订单不记该门槛 |

## 3. API 摘要

### 第二波

- 商品读写带 `stockQty`/`minQty`/`maxQty`
- 篮/下单：服务端校验起购限购库存；提交扣减；取消回滚
- `GET /api/v1/points/me` 余额+最近明细
- `POST /api/v1/points/redeem` `{ title, costPoints }`
- `GET|PUT` 商家店铺设置含 `pointsPerYuan`、`pickImageTtlMinutes`、`minDeliveryFen`
- 商家：`GET /api/v1/merchant/points/redeems`、`POST .../redeems/{id}/complete`
- 实景图：见 `2026-10-08-live-photo-design.md`（申请、站内信、提交新图）

### 第三波

- 券 CRUD / 领取 / 下单挂券
- `GET /api/v1/member-code` 会员码（含二维码）
- `POST /api/v1/checkins` 冒个泡；商家 `GET /api/v1/merchant/checkins/active`
- `POST /api/v1/merchant/points/counter` `{ code | checkinId, amountFen }` 按金额补记积分

## 4. 积分 / 券 / 收银补齐

- 积分入账基数是**优惠后应付**（预约单 `total - discount`，收银单 `payFen`）。比例是 `floor(floor(应付分/100) * points_per_yuan)`，比例最多两位小数；整数比例时与原来相同。顾客「我的积分」不在卡片上写比例。标题旁有说明图标，点开弹框，例如「每消费 1 元得 0.1 分」。
- 兑换物由商家配置（名称 + 所需积分）。从在售商品选入时，入口在添加卡片右上角，点开半屏搜索；名称与积分同一行手填。可停用或删除。待核销放在内容区右上角（「兑换物」同一行），有单时红点，点开半屏处理。半屏里写顾客昵称，没有昵称时写「微信用户」，不写「用户」加编号。顾客点选后只生成兑换申请并扣分，不生成预约单；到店由商家核销，或驳回并按 `CANCEL_REVERSAL` 退回。
- 顾客「我的积分」主页面只放当前积分和最近明细。「去兑换」「兑换记录」紧挨积分数字，点开半屏；兑换仍在「可兑换」半屏里完成。
- 商家优惠券页以列表为主。添加入口在内容区右上角（胶囊下方），点开半屏；券名称单独一行。面额、门槛、发放张数同一行。领取开始与领取截止同一行。使用截止单独一行，是已领取券的使用期限（当日结束前有效，不填则长期有效）；到期自动停用，未使用的领取改为过期。领取开始不填则立即可领；领取截止不填则一直可领到使用截止，使用截止也不填则不限领取。领取截止只停止新领取，已领未用的仍可用到使用截止。领取开始、领取截止都不能晚于使用截止。发放张数不填则不限，每人默认 1 张。未到领取开始、已过领取截止或已过使用截止的券不出现在顾客可领取列表。列表显示已领人数，有领取时段、使用截止或张数上限时一并显示。停用只停止新领取，已领取未使用的仍可使用。删除会作废未使用的领取；已核销的记录保留。正在订单或收银中使用的不能删。
- 顾客下单可选一张未使用的券，记为抵扣意向（`RESERVED` + `discount_fen`）。取消释放回 `UNUSED`；订单完成改为 `USED`。未满门槛不能挂。预约页把优惠券收成一行（已选显示减免金额，未选显示几张可用），点开半屏再选；半屏里券以面额卡片展示，未满门槛的写明还差多少且不能选。进入页面时默认勾上当前减免最多的一张可用券，顾客改过选择后保持其选择。
- 顾客可领取列表：还能领时按钮为「领取」。达到每人上限为「已领取」，总张数领完为「已领完」；两种都达到时显示「已领取」。这两种按钮不可再点。
- 顾客「我的」只放还能用的券，不写「未使用」。正在未完成预约或收银里占用的券仍留在这里，标成「使用中」；取消或作废后恢复可用，完成后再算已使用。页签下方有一行「历史优惠券」，点开半屏，里面是已使用、已过期以及其他失效的券。顾客不看到「已挂单」「已核销」。
- 到店补记积分：顾客在「我的」出示会员码，店员在「记积分」扫码后填收银机金额。扫不了时顾客点「冒个泡」，2 分钟内可在「给谁记」右上角的「正在冒泡」文字按钮里看到，点开半屏，带上头像和昵称，点中后半屏关闭，再填同一笔金额。有人冒泡时按钮出红点。顾客在「我的」身份卡点头像（微信选图）或昵称输入保存，`PUT /api/v1/me`。入账 `floor(floor(金额分/100) * points_per_yuan)`，流水原因 `COUNTER_SPEND`。不满 1 元、按比例向下取整后为 0，或店铺比例为 0 不入账。记完消耗这次冒泡。预约单完成仍走 `ORDER_COMPLETE`。不录商品、不核销券、不扣这里的库存。自建收银不再作为产品路径。

## 5. 验收（本波次）

第二波：商家可配库存与起购限购；超限加购被拒；下单扣库存、取消回滚；完成单入积分；顾客可见余额并可申请兑换；商品实景图按 `2026-10-08-live-photo-design.md` 可走通。  
第三波：可建券领取并挂到预约单；顾客可出示会员码或冒泡；店员可按收银机金额给该会员补记积分。
